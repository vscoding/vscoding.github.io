Build Project Shell Utilities

A concise reference for loading and using the public shell utilities provided by Build Project. The examples focus on supported usage and intentionally omit implementation details.

Initialization

The utilities use ROOT_URI as their base URI. Initialize it automatically with the bootstrap script:

source <(curl -sSL https://dev.kubectl.org/init)

Alternatively, set the variable manually:

export ROOT_URI="https://dev.kubectl.org"

The following examples execute remote shell code in the current session. Only source scripts from an endpoint you trust.

Usage Examples

Logging

Load the logging helper, then use log for a standard message or a level-specific helper for informational, warning, and error messages. Each call accepts a short context label followed by the message.

source <(curl -sSL "$ROOT_URI/func/log.sh") log "remark" "This is a log message." log_info "remark" "This is an informational message." log_warn "remark" "This is a warning message." log_error "remark" "This is an error message."

Checking Command Availability

Use command_exists before invoking an optional dependency. The logging helper can be used to report the result consistently.

source <(curl -sSL "$ROOT_URI/func/log.sh") source <(curl -sSL "$ROOT_URI/func/command_exists.sh") if command_exists docker; then log_info "check" "Docker is available." else log_error "check" "Docker is not available." fi

Usage Notes

  • Run the initialization step before loading any utility.

  • Use source to make the downloaded functions available in the current shell session.

  • Run the examples in a Bash-compatible shell that supports process substitution.
