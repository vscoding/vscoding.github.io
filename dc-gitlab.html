GitLab

GitLab 是集代码托管、代码评审和 CI/CD 于一体的 DevOps 平台。本示例部署 GitLab Community Edition，适合资源充足的单机环境。

环境变量

在 docker-compose.yml 同级目录创建 .env：

GITLAB_HOST=gitlab.example.com GITLAB_HTTP_PORT=8080 GITLAB_SSH_PORT=2224

GITLAB_HOST 应替换为客户端能够访问的域名或服务器地址。

Docker Compose 配置

services: gitlab: image: gitlab/gitlab-ce:latest container_name: gitlab hostname: "${GITLAB_HOST}" restart: unless-stopped environment: GITLAB_OMNIBUS_CONFIG: | external_url 'http://${GITLAB_HOST}:${GITLAB_HTTP_PORT}' gitlab_rails['gitlab_shell_ssh_port'] = ${GITLAB_SSH_PORT} ports: - "${GITLAB_HTTP_PORT}:8080" - "${GITLAB_SSH_PORT}:22" volumes: - "./config:/etc/gitlab" - "./logs:/var/log/gitlab" - "./data:/var/opt/gitlab" shm_size: "256m"

external_url 中的端口必须与宿主机 HTTP 端口一致。Omnibus GitLab 会根据该地址配置容器内监听端口，因此这里将同一个变量映射到容器端口。

启动与初始化

docker compose config docker compose up -d docker compose ps docker compose logs -f gitlab

首次启动可能需要数分钟。服务就绪后，访问 http://<GITLAB_HOST>:<GITLAB_HTTP_PORT>/ ，初始 root 密码可通过以下命令查看：

docker compose exec gitlab grep 'Password:' /etc/gitlab/initial_root_password

该密码文件会在首次重配置后 24 小时自动删除，登录后应立即修改密码。

HTTPS 配置

示例默认使用 HTTP。生产环境建议使用域名和 HTTPS，可以在 GitLab Omnibus 中配置证书，也可以在前置反向代理终止 TLS。采用反向代理时，应同步调整 external_url 和转发请求头；由 GitLab 直接终止 TLS 时，还需映射 HTTPS 端口并挂载证书。

注意事项

  • GitLab 对内存和存储资源要求较高，部署前应参考当前版本的硬件建议。

  • config、 logs 和 data 目录需要一起纳入备份与恢复方案。

  • 示例使用 latest 便于演示；长期运行时必须固定明确版本，并按官方升级路径逐级升级。

  • 如无需容器 Registry、Pages 等功能，不要额外开放对应端口。
