Kuboard

Kuboard 为 Kubernetes 集群提供可视化管理界面。本示例将 Web 服务映射到宿主机端口 8081 ，将 Agent Server 映射到端口 10081。

Docker Compose 配置

创建 docker-compose.yml：

services: kuboard: image: eipwork/kuboard:v3 container_name: kuboard privileged: true restart: unless-stopped volumes: - "./data:/data" ports: - "8081:80" - "10081:10081" environment: TZ: Asia/Shanghai KUBOARD_ENDPOINT: "http://172.100.1.100:8081" KUBOARD_AGENT_SERVER_TCP_PORT: "10081"

将 172.100.1.100 替换为 Kubernetes 节点能够访问的 Kuboard 宿主机内网地址。不要使用 127.0.0.1 或 localhost。

如果宿主机端口不是 10081， KUBOARD_AGENT_SERVER_TCP_PORT 必须同步填写新的宿主机端口。修改 KUBOARD_ENDPOINT 后，需要重新导入已有集群。

启动与访问

docker compose config docker compose up -d docker compose ps docker compose logs -f kuboard

通过 http://<服务器地址>:8081/ 访问 Kuboard。首次登录后应立即修改默认管理员密码。

Nginx 反向代理

以下配置将请求转发到同一宿主机的 8081 端口：

location / { proxy_pass http://172.100.1.100:8081/; client_max_body_size 10m; gzip on; } location /k8s-ws/ { proxy_pass http://172.100.1.100:8081/k8s-ws/; proxy_http_version 1.1; proxy_pass_header Authorization; proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade"; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; } location /k8s-proxy/ { proxy_pass http://172.100.1.100:8081/k8s-proxy/; proxy_http_version 1.1; proxy_pass_header Authorization; proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade"; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; gzip on; }

若使用域名作为 KUBOARD_ENDPOINT ，该域名必须能被 Kubernetes 集群中的 Agent 正确解析和访问。
