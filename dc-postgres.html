PostgreSQL

本示例使用基于 PostgreSQL 15 的扩展镜像，其中包含 PostGIS、TimescaleDB 等插件，并通过 host 网络提供数据库服务。

环境变量

在 docker-compose.yml 同级目录创建 .env ，不要将真实密码提交到版本控制：

POSTGRES_USER=postgres POSTGRES_PASSWORD=replace-with-a-strong-password POSTGRES_DB=postgres TZ=Asia/Shanghai

Docker Compose 配置

services: postgresql: image: registry.cn-shanghai.aliyuncs.com/svcops/postgres:15-ext container_name: postgres15 network_mode: host restart: always volumes: - "./data:/var/lib/postgresql/data" environment: POSTGRES_USER: "${POSTGRES_USER:-postgres}" POSTGRES_PASSWORD: "${POSTGRES_PASSWORD:?set POSTGRES_PASSWORD in .env}" POSTGRES_DB: "${POSTGRES_DB:-postgres}" TZ: "${TZ:-Asia/Shanghai}"

POSTGRES_PASSWORD 使用必填插值；变量缺失时， docker compose config 会直接报错，而不会以空密码启动实例。

启动与验证

docker compose config docker compose up -d docker compose ps docker compose exec postgresql sh -c 'pg_isready -U "$POSTGRES_USER" -d "$POSTGRES_DB"'

由于使用 network_mode: host ，PostgreSQL 默认直接监听宿主机端口 5432 ，无需配置 ports 。应通过防火墙和 PostgreSQL 访问控制限制连接来源。

数据与初始化

  • POSTGRES_USER、 POSTGRES_PASSWORD 和 POSTGRES_DB 仅在数据目录为空、数据库首次初始化时生效。

  • 修改 .env 不会自动修改已初始化数据库中的用户或密码。

  • ./data 包含数据库文件，升级或调整镜像前必须先备份。

性能调优

可以使用 PGTune 根据主机资源生成初始参数，再结合实际负载验证和调整。
