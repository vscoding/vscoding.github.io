TeamCity

TeamCity 是持续集成与持续交付平台。本示例同时部署 TeamCity Server 和一个 Build Agent，二者通过 Compose 内部网络通信。

准备目录

mkdir -p server/datadir server/logs agent/conf

如果容器无法写入挂载目录，应根据镜像内运行用户调整目录权限，而不是直接为目录设置全局可写权限。

Docker Compose 配置

创建 docker-compose.yml：

services: teamcity-server: image: jetbrains/teamcity-server:latest container_name: teamcity-server restart: unless-stopped environment: TEAMCITY_SERVER_MEM_OPTS: "-Xmx2g -XX:ReservedCodeCacheSize=640m" volumes: - "./server/datadir:/data/teamcity_server/datadir" - "./server/logs:/opt/teamcity/logs" ports: - "8111:8111" teamcity-agent: image: jetbrains/teamcity-agent:latest container_name: teamcity-agent restart: unless-stopped depends_on: - teamcity-server environment: SERVER_URL: "http://teamcity-server:8111" AGENT_NAME: "docker-agent-1" volumes: - "./agent/conf:/data/teamcity_agent/conf"

depends_on 只控制启动顺序，不代表 Server 已完成初始化；Agent 会持续重试连接。

启动与初始化

docker compose config docker compose up -d docker compose ps docker compose logs -f teamcity-server teamcity-agent

访问 http://<服务器地址>:8111/ ，按照页面提示完成数据目录、数据库和管理员账户初始化。示例使用 TeamCity 内置数据库，仅适合评估；长期使用应配置受支持的外部数据库。

初始化完成后，进入 Agents | Unauthorized 授权 docker-agent-1 ，Agent 才能执行构建。

在 Agent 中使用 Docker

默认 Agent 不能直接构建 Docker 镜像。如需访问宿主机 Docker，可以挂载 Docker Socket 并确保镜像中存在兼容的 Docker CLI，但这等同于向 Agent 授予宿主机 root 级控制能力。应优先使用隔离的构建节点或其他安全的容器构建方案，避免在共享服务器上直接挂载 /var/run/docker.sock。

数据与升级

  • server/datadir 保存项目配置和制品， server/logs 保存服务日志，二者应定期备份。

  • agent/conf 保存 Agent 身份；删除后，TeamCity 可能将其识别为新的 Agent。

  • 生产环境应为 Server 和 Agent 固定兼容的镜像版本，并先升级 Server，再升级 Agent。
