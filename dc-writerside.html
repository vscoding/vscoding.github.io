Writerside

Writerside 提供官方 Docker 构建器，可以在不依赖本地 IDE 的环境中检查并构建文档。本示例将 Dockerfile 封装为一次性的 Compose 构建任务。

准备 Dockerfile

在文档仓库根目录创建 Dockerfile：

FROM jetbrains/writerside-builder:2026.08.0328 CMD export DISPLAY=:99 && \ Xvfb :99 & \ /opt/builder/bin/idea.sh helpbuilderinspect --source-dir /opt/sources --product $INSTANCE --runner other --output-dir /opt/sources/output

构建器版本应与项目使用的 Writerside 版本保持一致。升级 Writerside 后，应同步更新镜像标签。

Docker Compose 配置

在同一目录创建 docker-compose.yml：

services: writerside-builder: build: context: . dockerfile: Dockerfile environment: INSTANCE: "${INSTANCE:-Writerside/blog}" volumes: - ".:/opt/sources"

INSTANCE 是实例配置文件相对于仓库根目录的路径，不包含 .cfg 扩展名。例如配置文件为 Writerside/blog.cfg 时，值应为 Writerside/blog。

构建与验证

先检查最终配置并构建镜像：

docker compose config docker compose build writerside-builder

执行一次文档检查与构建：

docker compose run --rm writerside-builder

任务成功后，构建产物写入仓库根目录的 output 。该服务是一次性任务，不应使用 docker compose up -d 常驻运行。

如需临时构建其他实例，可以覆盖环境变量：

INSTANCE=Writerside/another-instance docker compose run --rm writerside-builder

注意事项

  • 挂载的仓库目录可被容器写入，执行前应确认 Dockerfile 和依赖来源可信。

  • output 通常是生成目录，应根据项目发布流程决定是否加入版本控制。

  • CI 环境中应缓存 Docker 镜像层，但不要复用可能包含旧构建产物的 output 目录。
