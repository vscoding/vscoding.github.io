IP Anchor Domain Naming

本文约定标准 IP 锚点域名的命名空间、命名格式、字段和 DNS 记录写法。

标准 IP 锚点域名作为稳定对象的地址基准；便于记忆的简化域名和业务域名通过 CNAME 引用标准锚点。

示例统一使用 example.com 。实际落地时替换为自己的根域名。

基础规范

命名空间

保留四类核心命名空间：

命名空间

表达对象

用途

host.example.com

单个主机地址

主机 IP 锚点，例如 VPS、PC、NAS、Router、Gateway

wan.example.com

单个公网出口地址

公网出口 IP 锚点，例如家庭出口、办公出口、DDNS 出口

net.example.com

单个网络入口地址

网络入口 IP 锚点，例如 VPN、Tunnel、Proxy、SSH Gateway

pool.example.com

多个地址组成的目标组

多 IP 目标组，例如 DNS 轮询、入口集群、负载均衡目标组

不使用 svc.example.com 或 dyn.svc.example.com 。业务服务域名不纳入本规范；动态出口统一放在 wan.example.com 下。

本规范不定义端口、协议、环境、业务服务、证书和访问控制。业务服务可以引用 IP 锚点域名，但业务服务名不进入 IP 锚点域名本身。

命名约束

  • 全部使用小写字母、数字和连字符 -。

  • 单个标签不以连字符开头或结尾，不使用连续连字符；单个标签长度不超过 63 个字符，完整域名长度不超过 253 个字符。

  • identity 表达稳定实例身份，不使用 IP、端口、环境名或临时状态。

  • 不把 grafana、 registry、 api 这类业务服务名放进 IP 锚点域名。

  • 不把 prod、 dev 这类环境名放进 IP 锚点域名；环境信息放到标签、Inventory 或业务域名中。

  • host、 wan、 net 表达单个稳定对象； pool 表达多个地址组成的集合。

  • 主机存在多个地址时，使用 host-scope 区分内网、公网入站、公网出站及 VPN / Overlay 网络地址，例如 priv、 pub、 egress、 ts、 ovpn。

  • pool-scope 表达目标组成员的主要归组范围，可以按地域或自治系统划分。

  • pool 不固定 provider 字段，成员 IP 可以来自不同运营商、云服务商、网络平台、自治系统或地域。

  • pool 使用基础设施功能命名，例如 edge、 ingress、 proxy ，避免使用具体业务服务名。

字段与取值

本节按命名格式说明字段。 region、 provider、 identity 是跨多个命名空间复用的公用字段； pool 不使用 provider ，因为目标组成员的 IP 来源可能不同。

host-scope 用于选择同一主机在哪个网络中的地址，或该地址承担的用途。它不改变主机身份，也不表达具体业务服务、端口或地址族。 同一主机在不同作用域下保持相同的 host-id ；例如 nas-main.priv.host.example.com 和 nas-main.ts.host.example.com 分别引用同一台 NAS 的普通内网地址和 Tailscale 网络地址。 本文的 nas-main 示例均假定地域和提供方均未知，且简化后身份唯一，用于展示少用的简化格式；已知这些信息时应使用完整格式。

作用域取值与维护规则：

  • ts/tailscale、 ovpn/openvpn 等分别是同一网络类型的短写与全称，不代表不同网络。每套命名体系选择一种作为标准写法；本文示例统一使用短写。 如需兼容另一种写法，通过 CNAME 引用标准锚点，不重复维护地址记录。

  • priv 表达未按具体 VPN / Overlay 网络细分的内网地址，例如 LAN 或云 VPC 地址。需要同时管理普通内网与 VPN 地址时，分别使用 priv 和对应网络作用域。 不将 LAN、Tailscale、OpenVPN 等不同网络的地址混入同一个锚点；同一网络作用域仍可同时维护 A 和 AAAA。

  • 只有一种内网访问路径时，可以使用 priv 作为统一私网锚点；引入多个网络后，应明确其地址归属，避免让同一名称在不同网络之间含糊切换。

  • 同一主机加入多个同类网络且地址不同时，可在作用域后追加稳定网络标识，例如 ts-main、 ts-backup、 ovpn-office。 对应格式仍为 <host-id>.<host-scope>.host.example.com ，例如 nas-main.ovpn-office.host.example.com ；网络标识不使用 IP、端口、环境名或临时状态。

  • VPN / Overlay 作用域描述主机在该网络中的地址。VPN 连接入口使用 net ，公网出口使用 wan 或 egress.host ；连接到 VPN 不等于改变主机的公网出口。

  • provider 继续表达主机所属或所依托的提供方；同一台云主机加入 Tailscale 后，保留原有 host-id ，通过 ts 区分网络，无需把 provider 改为 tailscale。

  • 网络作用域不表达服务协议或业务名称。 ts、 ovpn、 wg 等只用于选择相应网络中的主机地址，不在域名中编码 VPN 连接参数。

priv 以及 VPN / Overlay 作用域的记录可能暴露内部地址、资产命名和网络结构，优先维护在私有 DNS、分视图 DNS 或内部解析区域。 在公网 DNS 中发布前，应确认允许公开这些信息；DNS 解析成功本身不保证网络可达或拥有访问权限。

<host-id>.host.example.com 可作为主机默认地址，并通过 CNAME 引用选定的作用域锚点；需要同时管理内网、公网入站、公网出站及 VPN / Overlay 网络地址时，优先使用显式作用域。

egress 用于标识主机访问外部网络时对端看到的公网 IP。它常用于第三方服务 IP 白名单、防火墙放行、审计排查和出口一致性检查。 egress 可以与 pub 相同，也可以指向 NAT Gateway、共享 EIP、家庭出口或办公出口等 wan.example.com 锚点。

DNS 记录约束

本规范以标准 IP 锚点域名为基础，统一管理对象身份及其地址映射。需要短名、习惯名称或业务名称时，建立 CNAME 指向对应的标准锚点，避免在多个别名下重复维护相同的 A/AAAA 记录。地址变化时，统一更新实际承载地址记录的标准锚点。

标准锚点之间也可以在地址语义一致时通过 CNAME 复用地址，例如主机的 egress.host 引用共享出口的 wan 锚点。

  • 同一记录名使用 CNAME 时，不应再同时维护 A、 AAAA 或其他记录。

  • pool 使用多条 A/AAAA 、DNS 服务商的权重记录、地理解析或健康检查能力实现目标组，不使用多条 CNAME 聚合多个主机锚点。

  • DNS 轮询不等于健康检查。需要自动摘除故障地址时，应使用 DNS 服务商健康检查、负载均衡能力或外部自动化同步。

  • CNAME 链路应尽量短，避免业务域名、 net、 wan、 host 之间形成难以排查的长链路。

  • 使用方需要指定地址族时，应查询同一锚点的 A 或 AAAA 记录自行选择，不额外定义 v4/v6 子命名空间。

推荐

原因

ipv4.tc.wh.example.com

home-wh-ct-main.wan.example.com

地址族不应放在首位，且 tc 易混淆

home-wh-ct-main.dyn.svc.example.com

动态出口是公网出口锚点，不是服务域名

服务名不应作为主机身份

IP 不应进入稳定域名

vps-hk-oracle-prod.host.example.com

vps-hk-oracle-edge.host.example.com

环境应通过标签、Inventory 或业务域名表达

grafana-global-main.pool.example.com

pool 应表达基础设施目标组，不表达具体业务服务
