调整 NodePort 端口范围

Kubernetes API Server 通过 --service-node-port-range 控制 NodePort Service 可以使用的端口范围，默认值为 30000-32767 。本文适用于由 kubeadm 管理、控制平面组件以静态 Pod 运行的集群。

修改前检查

先查看现有 Service 使用的 NodePort，避免缩小范围后遗漏已有配置：

kubectl get services --all-namespaces \ -o custom-columns='NAMESPACE:.metadata.namespace,NAME:.metadata.name,NODE_PORTS:.spec.ports[*].nodePort'

在每个节点上确认 Linux 临时端口范围：

cat /proc/sys/net/ipv4/ip_local_port_range

NodePort 范围不能与节点临时端口范围或其他宿主机服务端口冲突。本文按部署需求使用完整范围 1-65535 ，但这并不表示所有端口都可以安全分配：低位端口包含系统保留端口，其他端口也可能已被宿主机服务或临时连接占用。该配置只适合能够统一管理节点端口、防火墙和 Service 分配策略的环境。

更新 kubeadm 配置

编辑 kubeadm 保存的集群配置：

kubectl edit configmap kubeadm-config -n kube-system

在 data.ClusterConfiguration 的 apiServer.extraArgs 中记录相同范围。当前 kubeadm v1beta4 配置格式如下：

apiServer: extraArgs: - name: service-node-port-range value: 1-65535

较早的 v1beta3 配置使用映射格式：

apiServer: extraArgs: service-node-port-range: 1-65535

应以 ConfigMap 中现有的 apiVersion 和字段结构为准。同步 kubeadm 配置可以降低后续执行 kubeadm upgrade 时自定义参数被覆盖的风险。

更新 API Server 静态 Pod

登录控制平面节点，编辑 kube-apiserver 清单：

sudo vim /etc/kubernetes/manifests/kube-apiserver.yaml

在 kube-apiserver 容器的 command 参数列表中添加或修改以下参数，并确保只出现一次：

spec: containers: - command: - kube-apiserver - --service-node-port-range=1-65535

保存文件后，kubelet 会检测清单变化并重启本节点上的 kube-apiserver 静态 Pod。API Server 在重启期间可能短暂不可用。

高可用集群需要在每个控制平面节点上使用相同配置。应逐个节点修改，并确认当前节点恢复健康后再继续下一个节点。

验证配置

确认 API Server Pod 已恢复运行：

kubectl get pods -n kube-system \ --selector=component=kube-apiserver \ -o wide

检查 Pod 中实际生效的启动参数：

kubectl get pods -n kube-system \ --selector=component=kube-apiserver \ -o yaml | grep -- '--service-node-port-range=1-65535'

最后选择范围内一个已确认未占用的端口，通过 Server-side dry run 验证 API 校验。下面继续使用 20000 ，该命令不会持久化 Service：

kubectl create service nodeport node-port-range-check \ --tcp=80:80 \ --node-port=20000 \ --dry-run=server \ -o yaml

配置生效后，还需要同步调整节点防火墙、安全组和网络访问控制规则。
