管理节点污点

Kubernetes 调度器通过污点（taint）和容忍度（toleration）控制 Pod 能否调度到节点。kubeadm 默认在控制平面节点上添加 node-role.kubernetes.io/control-plane:NoSchedule ，避免普通业务 Pod 占用控制平面资源。

查看节点污点

将 k8s-master 替换为实际节点名称：

NODE_NAME=k8s-master kubectl get node "$NODE_NAME" \ -o jsonpath='{range .spec.taints[*]}{.key}{"="}{.value}{":"}{.effect}{"\n"}{end}'

也可以先列出节点，再确认控制平面节点名称：

kubectl get nodes -o wide

允许控制平面节点调度

单节点集群或资源有限的测试集群可能需要让控制平面节点同时承载业务 Pod。删除 kubeadm 当前使用的控制平面污点：

kubectl taint nodes "$NODE_NAME" node-role.kubernetes.io/control-plane-

旧版 kubeadm 可能仍使用已经弃用的 master 污点。仅当查看结果中存在该键时，再执行：

kubectl taint nodes "$NODE_NAME" node-role.kubernetes.io/master-

删除污点后，调度器可以把新 Pod 调度到该节点，但仍会综合资源请求、亲和性和其他调度约束。无需额外添加 node-role.kubernetes.io/worker 标签；节点角色标签只用于标识和选择节点，不决定它是否可调度。

恢复控制平面隔离

重新添加 NoSchedule 污点：

kubectl taint nodes "$NODE_NAME" \ node-role.kubernetes.io/control-plane:NoSchedule \ --overwrite

验证污点已经恢复：

kubectl get node "$NODE_NAME" \ -o jsonpath='{range .spec.taints[*]}{.key}{":"}{.effect}{"\n"}{end}'

NoSchedule 只阻止不具备对应 toleration 的新 Pod 调度到该节点，不会驱逐已经运行的 Pod。生产集群通常应保留控制平面污点；需要运行在控制平面上的系统组件应显式声明 toleration。
